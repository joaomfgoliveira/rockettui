## Phase Goal

Roadmap goal (verbatim): The TUI is customizable through three TOML files in `~/.config/rockettui/`, with built-in defaults.

User story: not framed. The ROADMAP `**Goal:**` line is not in "As a / I want to / so that" form, and the planner does not invent one. Run `/gsd-mvp-phase 2` if story framing is wanted; it does not change this plan's tasks.

This plan is the phase tracer: it builds the whole config pipeline (XDG path, file reads, TOML parse with positions, validation, `Config` into `App`, refuse-to-start error screen) and proves it end to end with one real setting (`message_layout`) in the running binary before any other plan adds keys. Plans 02-02 (config.toml consumers) and 02-03 (keymap.toml) build on it in parallel in wave 2; plans 02-04 and 02-05 (theme.toml) follow.

Wave note: this plan alone adds crates (`toml`, `chrono`); no later Phase 2 plan edits Cargo.toml or Cargo.lock.

<objective>
Load config.toml, keymap.toml and theme.toml from `$XDG_CONFIG_HOME/rockettui/` (or `~/.config/rockettui/`) through a pure, filesystem-free parser core with a thin IO shell; run on built-in defaults when files are absent; validate every config.toml key of D-12/D-13; collect every problem across all three files in one pass; and refuse to start on any invalid file with an in-TUI error screen that lists everything and exits 1 on any key.

Purpose: CONF-01, CONF-02, CONF-03 and the validation half of CONF-07, plus D-01, D-02, D-03, D-12, D-13. Plans 02-02..02-05 plug their keys into this pipeline without touching its shape.
Output: src/config/{mod,diag,paths,settings}.rs, `App::with_config`, `run(terminal, config)`, a main that loads config before the terminal, src/ui/error_screen.rs with a reviewed snapshot, test helpers, and pty scenarios config_layout and config_error with XDG isolation for every scenario.
</objective>
