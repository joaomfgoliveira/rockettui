src/app/input_buf.rs: `pub const MAX_INPUT_BYTES: usize = 64 * 1024;` and `pub const MAX_INPUT_ROWS: u16 = 5;` (flagged assumption A3). `pub struct InputBuffer { lines: Vec<String>, row: usize, col: usize, top: usize }` where lines always holds at least one line, col is a byte index on a grapheme boundary (unicode-segmentation) and top is the stored first visible visual row. Hand-written Debug printing only the line count and byte length (T-01-21). Editing methods (D-14): `new`, `is_empty`, `text` (lines joined with LF), `line_count`, `row`, `col`, `insert_char(c) -> bool` (first refuses line-break chars: LF, CR, U+2028 and U+2029 return false and change nothing, because the sanitizer maps CR, U+2028 and U+2029 to LF and keeps LF, which would otherwise put a line break inside one stored line; a line break enters the buffer only through `newline` or through `insert_str` splitting on LF, which keeps the invariant that no element of `lines` contains LF; every other char goes through `ui::sanitize::sanitize` like insert_str, so a char the sanitizer drops is ignored and a TAB becomes spaces; returns true when something was inserted and false when the char was refused, dropped or would exceed MAX_INPUT_BYTES), `insert_str(s) -> bool` (runs `ui::sanitize::sanitize` first, normalizes line endings, splits on LF into lines, truncates on a char boundary at the cap and returns true when truncated), `newline`, `backspace`, `delete_word_back` (skip whitespace leftwards, then non-whitespace; at column 0 join with the previous line), `delete_to_line_start`, `left`, `right` (by grapheme, crossing line ends; used by Insert-mode arrows), `up`, `down` (one logical line, keeping the display column via unicode-width; visual-row movement is out of scope, flagged A8), `home`, `end`, `take() -> String` (also resets top to 0). Geometry: `pub fn visual_rows(&self, width: u16) -> Vec<String>` hard-wraps each logical line by display width at grapheme boundaries (width treated as at least 1; a grapheme wider than the width gets its own row; an empty line is one empty row; the cursor line gets one extra empty row when the cursor sits at its end and that line's width is a non-zero multiple of the width); `pub fn cursor_visual(&self, width: u16) -> (u16, u16)` gives (x, y) in those visual rows, consistent with visual_rows; `pub fn view_top(&self, width: u16, height: u16) -> usize` starts from the stored top, moves it so the cursor's visual row lies inside `[top, top + height)`, then clamps to `rows.saturating_sub(height)` (pure, so the renderer and the reducer agree, mirroring `app::messages::view`); `pub fn half_page(&mut self, width: u16, height: u16, n: usize, forward: bool)` does nothing unless the visual row count exceeds `height`; otherwise with `delta = max(1, height / 2) * n` it sets top to `view_top` plus or minus delta (clamped to the valid range) and moves the cursor delta logical lines in the same direction with `move_line`. Character-level hard wrap (not word wrap) keeps cursor math exact (flagged A14). All index math is saturating.
