## Phase Goal

Roadmap goal (verbatim): A runnable ratatui app with the sidebar + messages + input layout, fake rooms, and Normal/Insert/Command modes. (No user story is framed in ROADMAP; see plan 01-01.)

This plan is the **second half of the Walking Skeleton** (see `SKELETON.md`). It leads with the binary tracer: `cargo run` -> layout listing the seeded rooms -> j/k -> `:q` -> restored terminal, proven by the pty smoke harness. It depends only on plan 01-01, and no expansion plan (01-03 onward) starts before it lands.

Scope note (file count): 13 files, below the 15-file blocker threshold but above the soft threshold of 10. Twelve of them are modules that the binary tracer must create or extend to reach the screen, counting src/test_util.rs, which this plan creates from plan 01-01's inline helpers so that plan stays at 14 committed files (each pane renderer is a small file so the parallel plans 01-04 and 01-05 can later own one each without touching a shared file); the 13th, src/ui/sanitize.rs, is task 2's choke point, which must exist before any later plan renders untrusted text. None of them can move to a later plan for free: removing a renderer or the harness breaks the tracer's end-to-end check, and moving the sanitizer would let plans 01-03..01-06 render unsanitized strings.

5. Run loop (src/lib.rs; Pattern 3, reordered to fix plan-check B1). Add `pub mod event; pub mod tui;`, `pub const CHANNEL_CAPACITY: usize = 256;`, a private `fn unix_now() -> i64` (whole seconds since the Unix epoch from the standard library's system clock, 0 on error; this file is the only place on the app path that reads a wall clock) and `pub async fn run(mut terminal: ratatui::DefaultTerminal) -> std::io::Result<()>`. In `run`, in this order: (a) create `tokio::sync::mpsc::channel::<Action>(CHANNEL_CAPACITY)`; (b) send every `data::fake::seed()` Action with `tx.send(a).await` (the D-13 seam: Phase 3 sends the same Actions from REST tasks; 10 seed Actions fit the capacity, so no send waits); (c) call `event::spawn_input_task(tx.clone())`, then drop the local sender; (d) `let mut app = App::new(terminal.size()?)`; (e) start `let mut batch: Vec<Action>` by draining `rx.try_recv()` until it is empty, which yields every seed Action because they were sent by this same task before the drain; (f) loop: apply `std::iter::once(Action::Clock(unix_now())).chain(batch.drain(..))` one Action at a time with `update(&mut app, a)`, stopping the batch as soon as `app.should_quit`; break when `should_quit`; `terminal.draw(|f| ui::view(f, &app))?`; then `rx.recv().await` (None ends the loop) into the batch followed by every Action `try_recv` still yields. The old draw-then-receive order drew a first frame with NORMAL and an empty sidebar, which is exactly what the harness check in step 7 rejects. Trust boundary for T-01-01 and T-01-02: every string from data or the user passes one choke point before width math or drawing. Write the listed tests first, watch them fail, then implement.
