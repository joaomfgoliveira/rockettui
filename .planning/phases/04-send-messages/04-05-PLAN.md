## Phase Goal

Roadmap goal (verbatim): User composes and sends messages to the open room.

User story: not framed (see plan 04-01).

This plan rounds out composing: the configurable follow-after-send policy (D-05), drafts that survive room switches (D-10), and the id dedupe in the message store that Phase 5 relies on (D-13, amended by D-21: the dedupe is state-aware, for every server message including history pages). Revision 1 renumbered this plan from 04-04 to 04-05 (plan 04-01 was split in two). Round 3 widened Task 3: the history merges in src/app/history.rs now follow D-21 too (they used to skip every held id, which left a delivered-but-Unconfirmed row unconfirmed), and a confirmed Sending copy keeps the room's in-flight slot until its POST answers (D-03). It runs in parallel with plan 04-06 (wave 4): the files do not overlap (plan 04-06 does not touch src/app/history.rs, src/app/mod.rs, src/app/messages.rs or src/app/send.rs; this plan does not touch src/app/update.rs or src/app/command.rs).

<objective>
Add the follow_on_send setting, per-room in-memory drafts and the D-13 merge rule with D-21's state-aware dedupe (absent: append; present and Sent: ignore; present and still pending: replace in place and mark Sent) applied to realtime-style arrivals and to history pages alike, plus the in-flight slot that keeps D-03 true after a Sending copy is confirmed, each wired through the reducer that uses it.

Purpose: MSG-02 with D-03, D-05, D-10, D-13 and D-21 (the user's amendment of D-13; it was research default (a) and is now a locked decision).
Output: Settings.follow_on_send (FollowOnSend), messages::is_at_bottom, messages::confirm_held, messages::merge_incoming, App.drafts and the open_room swap, App.awaiting_answer, send::submit, send::pump, send::on_sent and send::on_failed updates, history::on_loaded and history::on_older_page routed through confirm_held.

## Decision log

| Decision | How this plan applies it |
|----------|--------------------------|
| D-13 vs D-21 | D-13 as first written ignored any message whose _id is already present, which would leave a send whose REST answer was lost marked Unconfirmed even after Phase 5's realtime echo delivered it. The user amended it as D-21 (after the second plan check): the dedupe is state-aware. Task 3 implements D-21 exactly (absent: append; present and Sent: ignore; present and Queued, Sending, Failed or Unconfirmed: replace in place and mark Sent); D-13's plain ignore survives only for the already-Sent case. Round 3 (plan check, round 3): D-21 speaks of every incoming message, and a history load is reachable in phase 4 with a held pending copy (a send times out and stays Unconfirmed although the server stored it, then a refresh or older page returns it), so on_loaded and on_older_page now use the same rule through messages::confirm_held instead of skipping every held id. |
| D-03 with D-21 | At most one request in flight per room. Marking a Sending copy Sent by a server copy must not free the slot while its POST is outstanding, so confirm_held records the room and id in App.awaiting_answer, pump honors it, and the answer to that POST (on_sent or on_failed) releases it. A failure answer for a row that is already Sent shows no error: the server's own copy proved delivery. |
