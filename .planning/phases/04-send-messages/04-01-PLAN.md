## Phase Goal

Roadmap goal (verbatim): User composes and sends messages to the open room.

User story: not framed. The ROADMAP goal is not in "As a / I want to / so that" form; run `/gsd-mvp-phase 4` to frame one. It is not invented here (MVP rule).

This plan confirms the server contract the whole phase builds on with a Wave 0 probe, then wires the IO half of sending: a send effect goes through the client to chat.sendMessage, and the answer comes back through the reducer as an in-place swap or a status error. Plan 04-02 connects Insert-mode Enter to it (pending row, per-room queue, the real-binary `send` scenario) and so completes ROADMAP criterion 1. Plans 04-03 (retry, discard, unconfirmed outcome), 04-04 (pending/failed look), 04-05 (drafts, follow policy, id dedupe), 04-06 (own username), 04-07 (`:q` warning while messages are undelivered, D-20) and 04-08 (proof against the Docker server and UAT for criterion 2) expand it.

Task order note: the orchestrator requires the Wave 0 live probe to be the first task of the first plan (assumption A1 and the success-body shape are CITED, not VERIFIED). Task 1 is that probe; Task 2 is the tracer, the first implementation task; Task 3 makes client ids unique per run and extends the redaction sweep.
