## Phase Goal

Roadmap goal (verbatim): User composes and sends messages to the open room.

User story: not framed (see plan 04-01).

This plan replaces the `me` fallback author of pending rows with the user's real username, learned once per connection (D-17), so a sent message keeps its author, width and color when the server's copy swaps in. Revision 1 renumbered this plan from 04-05 to 04-06 (plan 04-01 was split in two); it runs in parallel with plan 04-05 (wave 4, no shared file). Its send_author scenario ends with a Failed row on screen; plan 04-07 (D-20) later changes that scenario's final quit to `:q!`, because a plain `:q` then warns instead of quitting.

<objective>
Load the own username with GET /api/v1/me at connect time and on :reconnect, keep it in App memory, author pending rows with it, and rename rows created before it arrived.

Purpose: MSG-02 with D-17 and D-08 (reconnect leaves sends alone; D-20's clarification of D-08 allows the username reload).
Output: MeResp, Client::me, Effect::LoadMe, Action::MeLoaded, the MeLoaded reducer arm, LoadMe at startup and in :reconnect, mock /me route and the send_author pty scenario.

File-count exception (scope_sanity, 10 files at the 10-file warning threshold): the files are the layers of one vertical slice, startup load to server call to effect to action to reducer, and cannot be split further without breaking it. Task 1's eight files carry the tracer: the wire type and client call (api/wire.rs, api/mod.rs), the effect and action (effect.rs, action.rs), the input vocabulary and reducer (input/actions.rs and app/update.rs, both of which match every Action variant exhaustively, so the new MeLoaded variant forces them in the same commit), the startup push (lib.rs) and the mock route plus pty scenario that prove it in the real binary (scripts/smoke_pty.py). Task 2 touches four files (app/update.rs and scripts/smoke_pty.py again, plus app/command.rs and src/redaction.rs), a handful of lines each. No file is listed for convenience; every one is named by a task.
</objective>
